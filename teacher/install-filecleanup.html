Canvas course file cleanup

Lists every file in your Canvas course by folder, oldest first, flags likely duplicates and files that are still linked in your content, and lets you delete the ones you no longer need. You reclaim course storage and keep the files you actually use easy to find. No account, no access token, nothing to install.

Beta

Install it

  1. Show your bookmarks bar. Press Ctrl + Shift + B, or Cmd + Shift + B on a Mac.
  2. Drag the blue Course file cleanup button below up onto that bar. That's the whole install. The tool lives inside that bookmark.

Then open any page inside your Canvas course and click the bookmark.

Can't drag it?

Some locked-down browsers block dragging. Right-click the button, choose Add Link to Bookmarks or Copy Link, and if you copied it, make a new bookmark and paste the copied text into its address field.

What it does

  • Lists every file in the course, grouped by folder and sub-folder, oldest first.
  • Flags likely duplicate sets, the Syllabus.docx, Syllabus-1.docx, Syllabus-2.docx pattern Canvas creates when you re-upload a name that already exists.
  • Flags files that are still linked from your syllabus, pages, assignments, discussions, announcements, Classic Quizzes, and modules, so you don't delete something in use.
  • Deletes the files you choose as a soft delete, restorable from Canvas's own Restore Deleted Items page.

What it can't check for links

The linked-in flag is honest about its blind spots. It does not check New Quizzes, question banks, rubrics, calendar events, or external tools. A file used only in one of those can show as unlinked, so give anything you're unsure about a second look before deleting it.

Getting a file back

A delete here is a soft delete. To restore one, add /undelete to the end of your course home page address (for example https://wwu.instructure.com/courses/12345/undelete) and choose Restore next to the file. That page lists only your most recently deleted items, about 25 of each type, and a restored file may need to be published again before students can see it.

Permissions and privacy

Running a tool somebody else wrote, inside a Canvas session you're signed in to, deserves a straight answer. Here it is.

  • It runs in your own Canvas session. No password, no token, no account to make. It uses the sign-in you already have, in the tab you already have open.
  • It sees only what your role can see. It asks Canvas for things the same way you do, as you, and it only deletes if your role already allows deleting files.
  • Deletes are soft deletes. It uses Canvas's restorable delete and never overwrites a file's contents. What you remove can be brought back from Restore Deleted Items.
  • It stores nothing and sends nothing out. The one request it makes outside Canvas fetches Western's brand typeface, Fira Sans, from this tool's own GitHub Pages site, not from any third party. No course information rides along, and the tool still works if your browser blocks it.
  • No remote code. The whole program lives inside the bookmark. You can read every line in the source.

Your institution hasn't reviewed this. If that matters where you work, ask your Canvas or IT team before you use it. I'd rather you ask than assume.

When it breaks

This is still being tested across different browsers and locked-down, IT-managed computers. If it doesn't work on your machine, that's useful to know. Tell me what happened: your browser, whether your computer is managed by your institution's IT, and what happened when you clicked. You won't break anything by trying.

Page look out of date? GitHub can keep showing an older copy for a few minutes after an update. Hard-refresh with Ctrl + Shift + R, or Cmd + Shift + R on a Mac.

Already installed? Your bookmark keeps the version you dragged. To update, drag the new button to your bar and delete the old one.
